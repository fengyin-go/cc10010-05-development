# 数据湖治理配置中心

离线版数据湖治理配置工具，涵盖多源接入通道、分层表结构设计、湖区分区策略、流批转换编排、元数据编目检索与资源计量管理，所有配置持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 原始表启用资格与快照门禁

「原始层管理 → 启用同步」不是简单改状态，启用前必须同时通过四项资格检查（策略集中在
`frontend/src/data/eligibility.ts`，纯函数、只判定不写数据）：

| 条件 | 判定规则 |
| --- | --- |
| 来源通道有效 | `来源通道` 填的是多源接入里已登记的 `通道编号`，且该通道当前为「运行中」 |
| 格式与压缩组合 | 文件格式 + 压缩类型在 `FORMAT_COMPRESSION_MATRIX` 允许表内（如 parquet+snappy、orc+zlib、csv+gzip）；csv+snappy 这类组合直接拒绝 |
| 目标路径唯一 | 归一化（忽略大小写/重复斜杠/尾斜杠）后不能与其他「已启用」表相同，也不接受绝对路径或带协议的外部地址 |
| 分区规则稳定 | 规则写成「字段=粒度/格式」（如 `dt=yyyy-MM-dd`、`dt=yyyy-MM-hh`、`dt=按天`）；只允许单个时间分区字段，格式必须含 `yyyy`，连续 61 个周期生成的分区文件路径必须互不相同 |

分区兼容条件同时限定字段粒度、保留天数和分区值范围：`retentionDays` 需落在
`RETENTION_POLICY`（hour 1-30 天、day 1-3650 天、month 28-3650 天、year 365-36500 天），
生成的分区值需落在 `PARTITION_VALUE_RANGE`（小时 0-23、日 1-31、月 1-12、年 1970-2100），
任一超出组合都不得启用。

启用动作是一个本地事务：

1. 四项资格通过 → 按目标路径加锁（内存锁 + `localStorage` 租约锁，15 秒过期）；
2. 拿到锁后重新读取最新数据再判定一次，相同目标路径并发启用时只有先进入事务的一张表通过；
3. 原始表置为「已启用」并写入 `数据校验`，同一次提交里在版本快照新增一条「待创建」快照
   （带 `目标表名`、`数据校验`、`来源表`、`校验令牌`）；
4. 写入失败回滚到事务前快照，原始层状态与待创建快照一起撤回，不会只写其中一边。

版本快照页对「提交创建 / 生效快照」加门禁：目标表名必须对应原始表中已启用、`数据校验`
以「通过」开头、且能查到启用事务生成的校验凭证的快照记录；原始表停用或被重新判定不合格后，
后续快照不能再生效。两个页面都会展示本次更新明细：原始层页展示四项资格逐条结果和生成的
待创建快照编号，版本快照页用「原始层启用同步本次更新」区块列出本次生成的待创建快照及门禁判定。

历史记录保持原口径：旧数据没有新增字段也能正常读取，评审后才逐步补齐校验字段。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `lake-govern-config:entries` 这一项，或调用 `resetModule(模块)`。
